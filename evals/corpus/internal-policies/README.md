# 사내 정보보호 규정 5종 — 평가 코퍼스

**합성 문서다.** 실제 은행의 사내 규정이 아니고, 실제 고객 데이터도 들어 있지 않다
(CLAUDE.md §5.2). 명세는 `docs/09-corpus-design.md`, 대조 결과는
`docs/09-corpus-verification.md`에 있다.

## 형식

- YAML front matter + Markdown 본문.
- **장 경계**: `## 제N장 제목`
- **조 경계**: `### 제N조(제목)` — 괄호 앞에 공백을 두지 않는다.
- **항**: `①②③…`, **호**: `  1. 2. 3.` (두 칸 들여쓰기)

3단계 검색이 문단 단위로 인용해야 하므로 조 경계는 위 한 형식만 쓴다. 표기가 흔들리면
같은 문서에서 어떤 조항은 잡히고 어떤 조항은 잡히지 않는다.

가지번호(제5조의2)는 쓰지 않는다. 골든셋 검사(`tests/unit/test_golden_dataset.py`)와
코퍼스 검사(`tests/unit/test_policy_corpus.py`)가 같은 전제를 공유한다.

## 왜 `evals/` 아래인가

이 문서들은 운영 데이터가 아니라 **평가 대상**이다. 3단계 이후 검색 재현율·인용 정확도·
근거 부족 판정이 전부 이 위에서 측정된다. `data/` 아래에 두면 수집 산출물과 섞이고,
`docs/` 아래에 두면 사람이 읽는 문서와 섞인다.

## 고칠 때

문서를 고치면 골든셋 15건의 전제가 함께 움직인다. 반드시 확인한다.

```bash
uv run pytest tests/unit/test_policy_corpus.py
```

이 테스트는 조 번호·제목의 참조 무결성, 난이도를 만드는 수치·주체·인용, EMPTY 영역의
공백, 그리고 **개정 대상 법령 조문을 인용하고 있지 않은지**를 검사한다. 마지막 항목이
특히 중요하다 — 자연스러워 보이는 인용 하나가 함정을 정답으로 바꾼다.
