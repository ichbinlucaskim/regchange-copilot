# 12. 위임 승격 측정 — R-22 를 문서 관계로 회수할 수 있는가

**결론부터: 3항목 중 1항목만 회수했다. R-22 는 열어 둔다.**

그리고 **회수하지 못한 2항목이 R-22 의 원인을 더 강하게 증명한다** — 후보를 18조로
좁혀도 정답이 7·8위였고, 점수 분포가 거의 평평했다(§3).

---

## 1. 측정 조건

| 항목 | 값 |
|---|---|
| 측정 일자 | 2026-08-21 |
| 러너 | `evals/runners/delegation_sweep.py` |
| 검색 | HYBRID, k=10, 임베딩 `KURE-v1` (ADR-015·016) |
| 시점 `as_of` | 2026-02-01 (3단계 측정과 동일) |
| 골든셋 | 15건 (IMPACT 10 / NO_IMPACT 2 / EMPTY 3) |
| 지표 | **재현율@k = IMPACT 10건의 케이스별 평균** (`docs/10-retrieval-evaluation-protocol.md` §4) |

**검색 규약을 고치지 않았다.** k·모드·임베딩·시점이 3단계와 같다. 승격은 검색
파라미터가 아니라 **후보를 추가하는 별도 조작**이며, 그래서 규약을 건드리지 않고
같은 지표로 비교할 수 있다.

**N=0 줄이 3단계 기준선(0.7667)과 정확히 일치한다.** 이것이 첫 번째 확인 사항이었다 —
승격 코드가 1차 검색을 건드리면 이 값이 달라진다.

## 2. 위임 그래프 — 4개 간선, 전부 문서 본문에서 나왔다

```
ISP-GUIDE-002 ──위임──▶ ISP-POL-001        (문서 단위)
ISP-GUIDE-003 ──위임──▶ ISP-POL-001        (문서 단위)
ISP-PROC-001  ──위임──▶ ISP-GUIDE-002      (문서 단위)
ISP-PROC-002  ──위임──▶ ISP-GUIDE-002 제35조 (조 지목)
```

| 항목 | 값 |
|---|---|
| 간선 | 4 |
| 위임 선언이 없는 문서 | `ISP-POL-001` 1건 — **최상위 문서이므로 정상** |
| 제1조가 없는 문서 | 0 |
| 상위 문서를 갖고 있지 않은 간선 | 0 |

**출처는 전부 `PARSED`** 다(ADR-007 의 출처 표시와 같은 계열). 근거 문장이 간선마다
함께 저장되며, 검토 화면이 "왜 이 조항이 올라왔는가"에 그 문장으로 답한다.

**메타데이터를 새로 만들지 않았다.** 위임 관계를 프론트매터에 적으면 같은 사실이 두 곳에
존재하게 되고 두 곳은 어긋난다. 본문이 정본이고 관계는 그 파생이다 — ADR-002 가
`text_raw` 를 정본으로 둔 것과 같은 방향이다. 자세한 근거는 ADR-017.

## 3. N 스윕 — 재현율과 정밀도를 함께 봤다

| N | 재현율@k | R-22 회수 | 후보 평균 | 승격 계 | 승격 정답 | 승격 오탐 |
|---|---|---|---|---|---|---|
| 0 | 0.7667 | 0/3 | 10.0 | 0 | 0 | 0 |
| 1 | 0.7667 | 0/3 | 11.2 | 18 | 0 | 18 무관 + 0 decoy |
| **2** | **0.8167** | **1/3** | 12.2 | 33 | 1 | 32 무관 + 0 decoy |
| 3 | 0.8167 | 1/3 | 13.3 | 49 | 1 | 48 무관 + 0 decoy |

**N=2 를 채택했다.**

- **N=1 은 순수 손해다.** 회수가 0인데 후보만 18개 늘린다.
- **N=3 은 N=2 와 재현율이 같다.** 무관 후보만 16개 더 붙는다.
- N=2 만이 회수를 만들고, 그 회수는 **1항목뿐이다.**

회수된 것은 `case-010` 의 `ISP-POL-001` 제5조(경영진의 책임)다. 1차 검색에서 **13위**였고
`ISP-GUIDE-003`(검색 3위)의 위임을 타고 `ISP-POL-001` 로 좁혀 재검색했을 때 2위로 올라왔다.

### 3.1 회수하지 못한 2항목 — **이것이 더 중요한 결과다**

`case-005` 의 `ISP-POL-001` 제8조·제15조는 N=3 까지도 회수되지 않았다. 왜인지 확인하려고
그 케이스의 질의로 `ISP-POL-001` **18조 전체**를 재검색해 순위를 봤다.

```
 1. 제6조  정보보호 최고책임자      0.0323
 2. 제9조  임직원의 의무            0.0315
 3. 제17조 정책의 검토 및 개정      0.0315
 4. 제2조  적용범위                 0.0313
 5. 제18조 위반 시 조치             0.0308
 6. 제4조  정보보호 기본원칙        0.0304
 7. 제8조  정보보호 조직            0.0294  ← 정답
 8. 제15조 인증 및 외부평가         0.0294  ← 정답
 …
18. 제3조  용어의 정의              0.0256
```

**점수 폭이 0.0323 ~ 0.0256 이다.** 18개 조가 사실상 구별되지 않는다. 후보를 152조에서
18조로 8배 좁혀도 정답이 7·8위이며, 이는 **신호가 묻혀 있던 것이 아니라 애초에 없다**는
뜻이다.

이것이 R-22 의 원인 진단(`docs/10-retrieval-evaluation-results.md` §5.3 — "질의는 수백 자짜리
구체적 개정문이고 정책 조항은 한 문장짜리 추상 선언")을 **더 강하게 확인한다.** 1차 측정은
"넓은 후보군에서 밀렸다"까지만 말할 수 있었지만, 이번에는 좁혀도 안 된다는 것을 봤다.

→ **정책 계층은 문단 유사도로 다룰 수 없다.** 회수하려면 유사도가 아닌 다른 신호가
필요하다. 조 단위 위임 선언이 그 신호가 될 수 있으나 이 코퍼스에는 `ISP-PROC-002` 제1조
한 곳뿐이며, 그것을 늘리는 것은 **문서를 고치는 일**이지 검색을 고치는 일이 아니다.

### 3.2 decoy 는 하나도 끌려오지 않았다

승격 문단 33건(N=2) 중 골든셋이 심어 둔 decoy 는 **0건**이다. 늘어난 32건은 정책 문서의
추상 선언들(제9조 임직원의 의무, 제17조 정책의 검토 및 개정 등)이다.

**이것을 "정밀도가 안 깎였다"로 읽으면 안 된다.** decoy 는 골든셋이 "그럴듯하다"고 판단해
심은 함정이며, 여기서 늘어난 것은 그보다 약한 후보들이다. 약한 후보가 프롬프트에 들어가면
모델이 그것을 인용할 수 있고, 그 인용은 gate 2단을 통과한다(실재하므로). **승격이 F-6
방향으로 얼마나 작용했는가는 검색 지표가 아니라 추출·평가 결과에서 재야 한다** —
`docs/12-impact-assessment-results.md` §6.

## 4. R-22 의 상태

**열어 둔다.** 회수 1/3.

| | 1차 측정 후 | 이번 측정 후 |
|---|---|---|
| 원인 | 확인됨 | 확인됨 (**더 강하게**) |
| 대응 | 미착수 | **착수, 부분 회수** |
| 잔여 | 3항목 | 2항목 |

대응 방향을 "미착수"에서 "부분 회수"로 바꾸되 리스크를 닫지 않는다. 2항목이 남아 있고,
그 2항목은 **같은 방법을 강화해서는 회수되지 않는다**(§3.1).

## 6. 다음에 할 것 — 이번 범위가 아닌 것

| 항목 | 왜 지금 하지 않는가 |
|---|---|
| 다단 승격(`PROC → GUIDE → POL`) | R-22 3항목은 전부 1단이면 닿는다. 관측되지 않은 필요를 위해 후보를 늘리지 않는다 |
| 조 단위 위임 선언을 코퍼스에 늘리기 | **문서를 고쳐 지표를 올리는 것**이다. 골든셋의 전제가 함께 움직인다 |
| 정책 계층 전용 질의(요약 질의) | 질의를 바꾸면 검색 규약이 바뀐다. 규약 §7 에 변경 이력을 남겨야 하는 변경이며, 먼저 "무엇을 요약할 것인가"의 근거가 필요하다 |
| 승격 문단에 별도 가중치 | 근거가 이 3항목뿐인 상수가 하나 더 생긴다 (R-22 가 애초에 파라미터로 풀지 말라고 한 이유) |
