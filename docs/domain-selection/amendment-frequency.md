### 사용한 API

### `regDt`의 의미 — 실측 확인

`lsJoHstInf`의 `regDt`는 **공포일자**다. 응답 안의 `공포일자`와 `조문개정일`이 전부
요청한 `regDt`와 일치한다 (예: 2026-01-06 응답의 법령 30건 전원 공포일자 20260106,
조문 206건 전원 조문개정일 20260106).

`lsHstInf`(법령 변경이력)의 `regDt`는 **공포일자가 아니다**. `regDt=20260105`로 조회한
34건의 공포일자가 20251230 · 20260106 · 20260102 · 20250224로 제각각이다.
법제처 DB 등록일로 보이나 **확정하지 못했다 — 미확인**.

### 실패 검증 — `lsJoHstInf`는 정상 0건과 실패가 구별되지 않는다

이 API의 성공 응답에는 `resultCode`·`page`·`numOfRows`가 **없다**. 정상 0건과 요청 실패
응답이 바이트 단위로 동일하다:

```xml
<LawSearch><target>lsJoHstInf</target><totalCnt>0</totalCnt></LawSearch>
```

0.7단계 리포트(edge-case #10)가 전제한 `resultCode` 기반 분류를 이 API에는 적용할 수 없다.
따라서 두 가지로 방어했다.

| 장치 | 내용 | 결과 |
|---|---|---|
| 응답 형태 분류 | 빈 본문 / HTML / XML 파싱 실패 / 루트 태그 불일치를 각각 실패로 기록 | 실패 **0일** |
| 0건 재요청 확인 | 0건인 날마다 독립적으로 한 번 더 요청해 같은 0인지 확인 | 161일 전부 재확인 |
| 카나리아 | 30일마다 2025-04-01(0.7단계에서 totalCnt=83 확인, 측정 구간 밖) 호출 | **14회 전부 통과** |

`lsHstInf`를 교차 확인에 쓰려던 최초 설계는 폐기했다 — 위와 같이 `regDt` 의미가 달라
상시 불일치가 발생한다.

### C-3. 날짜 기준 감지가 가능한가 → **가능하다**

`admrul` 목록 조회(`admrulListGuide`)에 날짜 파라미터가 있다.

| 파라미터 | 의미 | 실측 |
|---|---|---|
| `prmlYd` | **발령일자 기간검색** (`20250801~20260731`) | O 동작, totalCnt **7,087** |
| `modYd` | **수정일자 기간검색** | O 동작, totalCnt **7,762** |
| `date` | 발령일자 단일 | X 미확인 |
| `nw` | 1=현행 / 2=연혁 | O 동작 (연혁 버전 조회 가능) |
| `org` | 소관부처 | O 동작 — `prmlYd` + `org=1160100` → **52건** |
| `knd` | 1=훈령/2=예규/3=고시/4=공고/5=지침/6=기타 | X 미확인 |

응답 필드에 `발령일자`·`시행일자`·`생성일자`·`제개정구분명`·`현행연혁구분`이 있다.
`admrul` 목록 응답은 `lsJoHstInf`와 달리 루트가 `AdmRulSearch`이고 **`resultCode`·`page`·
`numOfRows`를 포함**한다.

0.7단계에서 상정했던 "목록을 주기적으로 돌려 `발령일자`/`시행일자`/`생성일자` 변화를
감지" 방식 외에, **기간을 직접 질의하는 파라미터(`prmlYd`)가 존재한다**는 것이 실측으로
확인됐다.

**미확인 항목**: `prmlYd`가 반환하는 7,087건이 발령일 기준 전수인지, `modYd`의 7,762건과의
차이(675건)가 무엇인지 확인하지 않았다. 조문 단위 변경 내역은 이 API가 제공하지 않는다.

### C-4. 행정규칙 후보 4종의 12개월 개정 횟수

집계 방법: `target=admrul`에 `query=<규칙명>`, `nw=1`(현행)과 `nw=2`(연혁)를 각각 호출하고

## E. 측정의 한계

### E-1. 12개월이 대표성이 있는가 — 확인되지 않았다

- 2025-10과 2025-12 두 달이 법령 이벤트의 47.7%, 조문 이벤트의 60.0%를 차지한다.
  단일 날짜(2025-10-01)가 조문 이벤트의 **43.5%**(15,528/35,681)다.
- 이런 대형 이벤트가 몇 년에 한 번인지, 매년 발생하는지는 **이 측정으로 알 수 없다.**
  복수 연도를 측정하지 않으면 알 수 없는 값이다.
- 후보 코퍼스별 개정 횟수(3~17회)는 표본이 작아 연도 간 변동을 추정할 수 없다.

### E-2. 놓쳤을 수 있는 경로

| 경로 | 상태 |
|---|---|
| `regDt` = 공포일자이므로, **공포 없이 시행일만 도래하는 변화**는 이 측정에 잡히지 않는다 | 미확인 — 그런 사례가 존재하는지 확인하지 않았다 |
| 조문 단위 변경이 없는 개정(제명 변경, 부칙만 개정 등) | 미확인 — `lsJoHstInf`가 이를 포함하는지 확인하지 않았다 |
| 별표·서식만 개정된 경우 | 미확인 — 0.7단계에서 별표가 조문과 별도 트리임을 확인했으나(ADR-004), 이 API가 별표 변경을 조문 이벤트로 내는지 확인하지 않았다 |
| 행정규칙의 **조문 단위** 변경 | **불가능** — `admrul`은 조문 단위 이력을 제공하지 않는다. C-4의 수치는 문서 단위 발령 횟수다 |
| `lsHstInf`(법령 변경이력)에만 나타나는 이벤트 | 미확인 — `regDt` 의미가 달라 대조하지 못했다 |

### E-3. 데이터 자체의 한계

- 같은 날 같은 법령ID가 중복 `<law>`로 나타나는 건이 48건 있다. 원인 **미확인**.
- `소관부처명`이 복수 부처를 쉼표로 나열하므로, 부처별 집계는 필드 값 문자열 기준이며
  부처 단위로 분해한 것이 아니다.
- 부처명이 측정 구간 중 변경된 것으로 보이는 값이 있다(재정경제부/기획재정부,
  성평등가족부/여성가족부, 산업통상부/산업통상자원부, 기후에너지환경부/환경부가
  모두 별도 값으로 관측됨). 같은 부처인지 **확인하지 않았다.**
- 행정규칙 집계는 `행정규칙명` 정확일치로 필터했으므로, 규칙명이 개정으로 바뀐 경우
  누락된다. **확인하지 않았다.**

### E-4. 빈도는 관련성을 보장하지 않는다

이 측정은 **"몇 번 바뀌었는가"를 셌지 "무엇이 바뀌었는가"를 보지 않았다.**
`제개정구분명`으로 타법개정을 걸러낸 것이 전부이며, 실질개정 안에서 그 내용이 정보보호·
전자금융 담당자에게 관련 있는지는 이 측정의 대상이 아니었다.

**실증 (2-A단계)**: 전자금융거래법(010199)의 12개월 유일한 자체 개정
(2025-12-16 공포 제21205호, MST 280277, 시행 2026-12-17)의 **15개 조문이 전부
선불충전금·정산자금 보호 계열**이었다.

| 조문 | 제목 |
|---|---|
| 제25조의2 / 제25조의4 / 제25조의5 | 선불충전금의 보호 / 정산대상금액의 보호 / 보호조치의 고지의무 |
| 제36조의3 | 전자지급결제대행업자의 행위규칙 |
| 제42조 / 제42조의2 | 회계처리 구분 및 건전경영지도 / 이용자 등의 보호 |
| 제2조·제3조·제28조·제30조·제32조·제33조의3·제43조·제49조·제51조 | 정의·적용범위·허가·등록·자본금·취소·벌칙·과태료 |

**제21조(안전성의 확보의무)와 제21조의2(정보보호최고책임자 지정)는 건드리지 않았다.**
정보보호부 관점에서 이 법률의 12개월 개정 실적은 **정보보호 의무 변경 0건**이다.

근거: `tests/fixtures/law_api/law_010199_mst280277.xml`,
시나리오 `evals/datasets/golden/case-015.yaml`.

**코퍼스 선택 근거(ADR-008)는 유지된다.** 이것은 결론의 번복이 아니라 근거의 한계를
적는 것이다 — B-1표의 개정 빈도는 여전히 사실이고, 후보 5개 중 정보보호·전자금융이
2위였다는 비교도 사실이다.

두 가지가 따라 나온다.

1. **소관 판단은 법령 단위가 아니라 조문 단위여야 한다.** "전자금융거래법은 정보보호부
   소관"이라는 법령 단위 규칙으로는 이 개정을 관련 있는 것으로 잘못 분류한다.
2. **운영 시작 후 "포착 건수 중 관련 있는 개정의 비율"을 별도로 측정한다.**
   이 비율이 낮으면 코퍼스 조정 신호다. 빈도가 높아도 관련성이 낮은 법령은 담당자에게
   소음이 되고, 소음이 쌓이면 알림 자체를 안 보게 된다.
