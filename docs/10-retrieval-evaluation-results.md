# 10-R. 검색 품질 측정 결과 — 1차 (LLM 없음)

채점 기준은 `docs/10-retrieval-evaluation-protocol.md` 에 **측정 이전에** 고정했다.
이 문서는 그 규약으로 잰 결과와 실패 분석만 담는다. 지표 정의나 k 를 여기서 바꾸지 않는다.

**이 단계에는 LLM 이 없다.** 검색만 잰다. 검색이 나쁜데 생성부터 손대면 원인을 영영
찾을 수 없기 때문이며, 파서를 먼저 만들고 정확도 1.0000 을 확인한 뒤 클라이언트로
넘어간 것과 같은 순서다.

결정은 ADR-015(임베딩)와 ADR-016(검색 결합)에 남겼다.

---

## 1. 측정 조건

| 항목 | 값 |
|---|---|
| 측정 일자 | 2026-08-20 |
| 기준 커밋 | `9b638cf` + 3단계 작업분 |
| 코퍼스 | `evals/corpus/internal-policies/` 5종 **152조** |
| 골든셋 | `evals/datasets/golden/` **15건** (IMPACT 10 / NO_IMPACT 2 / EMPTY 3) |
| 청킹 단위 | **조** (`### 제N조(제목)` 경계) |
| 검색 시점 `as_of` | 2026-02-01 (고정. 실행일을 쓰면 재현이 깨진다) |
| 결정 지표 | **재현율@10**, 동률 시 DECOY 혼입률@10 |
| 임베딩 후보 | `BAAI/bge-m3` / `nlpai-lab/KURE-v1` (둘 다 1024차원 · MIT · 로컬) |
| 어휘 검색 | 문자 2-gram BM25 (`k1=1.2`, `b=0.75`, 문헌 표준값) |
| 결합 | RRF (`k=60`, Cormack et al. 2009) |

**비용**: **0원.** 두 모델 모두 로컬이다. 152조 색인이 각각 약 30초
(Apple Silicon MPS, 모델 내려받기 제외), 질의 건당 수백 밀리초. 골든셋 15건을 세 방식으로
전부 재는 데 1분이 안 걸리므로 **반복 측정이 무료다** — 6단계 확장에서도 측정을 아낄
이유가 없다.

## 2. 1단계 — 임베딩 확정 (벡터 단독으로만 비교)

| 모델 | **재현율@10** | 정밀도@10 | DECOY@10 | MRR | hit@1 | EASY | MEDIUM | HARD |
|---|---|---|---|---|---|---|---|---|
| `bge-m3` | 0.7167 | 0.1800 | 0.3556 | 0.7583 | 0.60 | 1.0000 | 0.6190 | 0.6522 |
| **`KURE-v1`** | **0.7667** | 0.1900 | 0.3556 | 0.7400 | 0.60 | 1.0000 | **0.6667** | **0.6957** |

**KURE-v1 채택.** DECOY 혼입률이 같아 tie-break 는 발동하지 않았다.

KURE-v1 은 bge-m3 를 한국어로 파인튜닝한 모델이고 차원·시퀀스 길이·파라미터 수가 전부
같다. 따라서 이 대조의 변수는 **한국어 특화 학습 하나뿐**이며, 이득이 나타난 자리도
그에 부합한다 — **MEDIUM(법령과 다른 어휘를 쓰는 조항)에서 갈렸다**(0.6190 → 0.6667).
EASY 는 둘 다 1.0000 으로 천장이었다.

> 상용 API 임베딩은 후보에서 제외했다. 운영에서 쓸 수 없기 때문이며, 그 판단과 남는
> 공백은 ADR-015 에 적었다.

## 3. 2단계 — 검색 결합 (임베딩은 KURE-v1 고정)

| 방식 | **재현율@10** | 정밀도@10 | **DECOY@10** | MRR | hit@1 | 재현율@5(참고) |
|---|---|---|---|---|---|---|
| VECTOR | **0.7667** | 0.1900 | 0.3556 | 0.7400 | 0.60 | 0.6333 |
| LEXICAL | 0.7333 | 0.1800 | 0.3556 | 0.7833 | 0.70 | 0.5083 |
| **HYBRID** | **0.7667** | 0.1900 | **0.3333** | 0.7833 | 0.60 | 0.7000 |

**재현율@10 이 동률이다.** 사전 고정한 tie-break(DECOY 혼입률@10)가 하이브리드를 골랐고,
규칙대로 채택했다. **차이는 근소하며, 이 채택이 약하다는 사실을 ADR-016 에 명시했다.**

### 난이도별 (항목 단위)

| 유형 | n | VECTOR | LEXICAL | HYBRID |
|---|---|---|---|---|
| EASY | 5 | **1.0000** | **1.0000** | **1.0000** |
| MEDIUM | 21 | 0.6667 | 0.6190 | 0.6667 |
| HARD (여러 문서에 걸친 케이스의 항목) | 23 | 0.6957 | 0.6522 | 0.6957 |

**난이도 설계가 작동한다** — EASY 1.0000 vs MEDIUM 0.6667. EASY 5항목은 세 방식 모두
1~2위로 잡았다. 골든셋 README 가 "이 케이스를 못 잡으면 나머지는 볼 필요가 없다"고 한
기준선(ISP-PROC-002 제7조)을 통과했다.

### 하이브리드는 순증이 아니라 교환이었다

| 케이스 | 항목 | 결과 |
|---|---|---|
| 012 | ISP-GUIDE-002 제31조 | 하이브리드가 **회수** (벡터 51위 / 어휘 1위) |
| 010 | ISP-POL-001 제5조 | 하이브리드가 **잃음** (벡터가 잡았으나 어휘 26위에 밀려 RRF 에서 탈락) |

RRF 는 한쪽 목록에만 있는 항목에 구조적으로 불리하다. **상보성이 있다고 해서 하이브리드
이득이 보장되지 않는다는 것**이 이 측정의 내용이며, 재지 않고 채택했다면 몰랐을 사실이다.

### 정답 집합이 빈 5건 (규약 §5 — 재현율·정밀도를 계산하지 않는다)

| 케이스 | 정답 | DECOY@10 V / L / H |
|---|---|---|
| 003 | NO_IMPACT | 1.00 / 1.00 / 1.00 |
| 011 | NO_IMPACT | 1.00 / 1.00 / 1.00 |
| 013 | INSUFFICIENT_EVIDENCE | 0.50 / 0.50 / 0.50 |
| 014 | INSUFFICIENT_EVIDENCE | 0.00 / 0.67 / 0.67 |
| 015 | INSUFFICIENT_EVIDENCE | 0.33 / 0.67 / 0.33 |
| **평균** | | **0.5667 / 0.7667 / 0.7000** |

**이 5건만 보면 벡터 단독이 낫다**(0.5667 vs 0.7000). 사전 규칙이 tie-break 를 전 15건
평균으로 지정했기 때문에 판정에 들어가지 않았다. **규약 설계의 결함으로 기록하고 6단계에
반영한다** — 지금 고치면 결과를 보고 규칙을 고치는 것이 된다 (규약 §7, ADR-016).

**경계 판정**(규약 §6, case-002 의 ISP-GUIDE-002 제11조)은 세 방식 모두 top-10 에
들어오지 않았다. **경계 혼입 0건**이므로 이번 반영에서 판정을 확정할 재료가 없다.

## 4. `INSUFFICIENT_EVIDENCE` 를 점수로 가를 수 없다 — 이번 측정의 가장 중요한 발견

| 방식 | IMPACT 10건 top-1 평균 | 정답 없는 5건 top-1 평균 | 간격 |
|---|---|---|---|
| VECTOR | 0.7345 | 0.5984 | 19% |
| HYBRID | 0.0326 | 0.0322 | **1.2%** |

벡터 점수의 간격은 평균으로 보면 있지만 **개별 케이스에서 무너진다.**
**case-003 은 정답이 NO_IMPACT 인데 top-1 이 0.776 으로 IMPACT 평균(0.7345)을 넘는다.**
당연하다 — case-003 은 case-002 와 **같은 조문(제45조의3)** 의 타법개정이고 조문 경로도
어휘도 거의 같다. 골든셋 README §4.2 가 심어 둔 대조쌍이 정확히 여기서 값을 했다.

**결론: "유사도가 낮으면 근거 없음"이라는 임계값 규칙을 만들면 안 된다.**
`INSUFFICIENT_EVIDENCE` 는 점수가 아니라 **gate 구조**(3단계 §6, 기획서 8.1)로 판정한다.
이 측정이 그 설계 결정을 사후 정당화가 아니라 **사전 근거**로 뒷받침한다.

RRF 점수는 순위의 함수라 케이스 간 비교가 아예 의미를 갖지 않는다. 하이브리드 채택은
**그 유혹을 구조적으로 없앤다** — 이득으로 기록한다.

임계값을 도입하자는 제안은 이 표를 반증하는 측정과 함께 와야 한다.

## 5. 실패 분석 — 원인을 셋으로 나눈다

`limit=152` 로 다시 돌려 **정답 항목이 실제로 몇 위였는지** 전부 뽑았다.
"못 찾았다"와 "가까스로 밀렸다"는 다른 문제이고 조치도 다르다.
(진단용 실행이며 채점 k 는 규약대로 10 이다.)

### 5.1 두 방식은 서로 다른 것을 놓친다 — 상보성

| 케이스 | 항목 | 벡터 순위 | 어휘 순위 |
|---|---|---|---|
| 012 | ISP-GUIDE-002 제31조 | 51 | **1** |
| 008 | ISP-PROC-002 제8조 | 51 | **6** |
| 002 | ISP-PROC-001 제6조 | 79 | **7** |
| 002 | ISP-POL-001 제6조 | **3** | 23 |
| 007 | ISP-GUIDE-003 제5조 | **2** | 16 |
| 007 | ISP-POL-001 제7조 | **5** | 11 |

한쪽이 1~7위로 잡은 것을 다른 쪽이 11~79위로 놓친다. **양방향으로 일어난다.**
그럼에도 결합 이득이 순증으로 나타나지 않았다는 것이 §3 의 내용이다.

### 5.2 세 방식이 모두 놓치는 항목 — 구조적 실패

| 케이스 | 항목 | V / L 순위 | 원인 분류 |
|---|---|---|---|
| 001 | ISP-PROC-002 제8조 (대외 통지) | 11 / 18 | **검색** — 어휘 완전 불일치("이용자 통지"↔"고객 안내") |
| 004 | ISP-PROC-001 제24조 (외부 심사 대응) | 72 / 45 | **명세(의도)** — "인증" 어휘 부재 |
| 005 | ISP-POL-001 제8조 (정보보호 조직) | 45 / 71 | **문서 계층** |
| 005 | ISP-POL-001 제15조 (인증 및 외부평가) | 94 / 52 | **문서 계층** |
| 010 | ISP-POL-001 제5조 (경영진의 책임) | 11 / 26 | **문서 계층** |

**청킹이 원인인 실패는 하나도 없었다.** 조 단위가 너무 커서 잡음이 섞인 사례
(재검토 신호로 정해 둔 형태 — `retrieval/corpus.py`)는 관측되지 않았다.
조 단위 결정은 이번 측정에서 유지된다.

case-001 의 ISP-PROC-002 제8조는 **11위**로 가까스로 밖이다. 순위를 못 매긴 것이 아니라
밀린 것이며, k 를 바꾸면 들어온다 — 그러나 결과를 보고 k 를 바꾸지 않는다(규약 §3).

### 5.3 `ISP-POL-001` 이 반복 실패한다 — 문서 계층 비대칭 (R-22)

`ISP-POL-001` 은 정책 최상위 문서이고 **조 평균 95자, 중앙값 78자, 최소 35자**다.

```
제5조(경영진의 책임)  — 54자
  경영진은 정보보호 및 개인정보 보호의 중요성을 인식하고, 정보보호 활동에 필요한 자원을 지원한다.

제15조(인증 및 외부평가) — 46자
  은행은 정보보호 수준을 객관적으로 검증하기 위하여 필요한 인증을 취득하고 유지한다.
```

질의는 수백 자짜리 구체적 개정 조문이고, 대상 문단은 한 문장짜리 추상 선언이다.
**어휘 겹침도 의미 밀도도 구조적으로 낮고, 두 방식이 같은 방향으로 실패한다** —
따라서 하이브리드로도 풀리지 않는다.

**골든셋 명세의 비현실성으로 보지 않는다.** 골든셋의 `why` 가 이미 "정책 계층이라 어휘가
추상적이고 인용도 없어 매칭이 어렵다"(case-010)라고 적었다. 난이도를 알고 심은 것이며
MEDIUM 으로 분류돼 있다.

검색 파라미터로 고치려 하면(짧은 문단 가산점, 임계값 조정) 잘 동작하는 케이스의 정밀도를
깎는다. **한 실패를 고치려고 지표 전체를 움직이는 상수를 넣는 것**이다.
**R-22** 로 등재하고 대응 방향(문서 위임 관계를 타고 올라가는 경로)만 적어 두었다 —
`docs/04-risk-register.md`.

## 6. 아직 확정하지 않은 것

| 항목 | 상태 |
|---|---|
| 목표 재현율 | **미설정.** 파이프라인 전체 기준(기획서 12.2 의 0.85)은 검색 단독 기준이 아니다. 4단계에서 gate 통과율과 함께 정한다 |
| 변경 범위 질의 | 2회차 과제. `before` 3건 확보 후 같은 규약으로 재측정 (규약 §2) |
| DECOY 혼입률의 정답 유무별 분리 | 6단계에 반영 (§3, ADR-016) |
| 상용 API 임베딩과의 격차 | **의도적 공백.** 운영에서 쓸 수 없어 재지 않았다 (ADR-015) |

## 7. 재현

```bash
make up && make migrate
uv sync --group eval
uv run python -m evals.runners.policy_index --embed bge-m3
uv run python -m evals.runners.policy_index --embed kure-v1
uv run python -m evals.runners.retrieval_eval --embed bge-m3  --mode vector
uv run python -m evals.runners.retrieval_eval --embed kure-v1 --mode all
```

원시 결과는 `evals/results/retrieval-*.json` 에 케이스별로 남는다
(커밋하지 않는다 — `evals/runners/__init__.py` 의 판단).
