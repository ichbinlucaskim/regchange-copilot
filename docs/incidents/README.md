# 사건 기록

이 디렉터리는 프로젝트 진행 중 발견된 결함과 **그 발견 경위**를 기록한다.

## 왜 남기는가

설계 원칙은 위반될 때 비로소 검증된다.
이 프로젝트가 세운 원칙(재현율 우선, 순서 보존, 페이지네이션 완주)이 실제로 위반되었고
그것을 발견한 기록이 여기 있다.

**원칙을 지켰다는 주장보다, 원칙을 어겼다가 발견하고 고친 기록이 강하다.**

## 작성 규칙

- 사건을 축소하거나 미화하지 않는다. 틀린 값과 맞는 값을 나란히 적는다
- **어떻게 발견되었는가**를 반드시 적는다. 원인보다 이 항목이 더 중요하다 —
  같은 유형의 미지의 결함을 잡는 방법이 거기 있다
- 확인하지 못한 것은 "미확인"으로 표시한다

**미수도 적는다.** 같은 기전이 재발했으나 결론이 틀리지 않은 경우다. 값이 맞았다는
이유로 지우면 "우리 방어가 잡았다"와 "이번엔 운이 좋았다"를 구별할 수 없게 된다.
미수는 사건 번호를 받지 않으며, **왜 틀리지 않았는지**를 반드시 적는다.

## 사건의 계열

| 계열 | 성질 | 원본 | 대응 |
|---|---|---|---|
| 조용한 누락 (`silent-undercounting.md`) | 적게 셌다 | 남아 있다 | **탐지** — 다른 방식으로 다시 센다 |
| 조용한 파괴 (`test-truncated-operations-history.md`) | 있던 것이 사라졌다 | 없다 | **예방** — 탐지로는 늦다 |
| 전제의 낡음 (`llm-api-schema-drift.md`) | 우리가 믿은 외부 사실이 더 이상 사실이 아니다 | 해당 없음 | **실측** — 착수 전에 외부 계약을 다시 읽는다 |
| 전제의 낡음 — 내부 (`assumptions-that-crossed-a-boundary.md`) | **우리가 정한 근거**가 다른 단계에서 더 이상 성립하지 않는다 | 남아 있다(docstring) | **재확인** — 상수·예외 범위를 재사용할 때 그 근거를 인용해 유효성을 적는다 |
| **안전망의 침묵** (`safety-net-silently-disabled.md`) | **방어 장치가 돌지 않는다** | 해당 없음 — 아무 일도 일어나지 않았다 | **발화 확인** — 「울리지 않았다」를 정상으로 읽지 않는다. 그 이력에서 실제로 울리는지 테스트로 고정한다 |

앞의 계열은 재계산으로 되돌아온다. 가운데 계열은 되돌아오지 않으므로 사후 확인이
아니라 **작업 전 가드**가 유일한 수단이다.

**마지막 계열은 셋 중 어느 것도 아니다.** 재계산할 값이 없고 파괴된 것도 없다 —
**일어나야 할 일이 일어나지 않았을 뿐**이며, 그 부재는 정상과 구별되지 않는다.
그래서 유일한 수단이 **발화 테스트**다: 안전망을 만들 때 「그 이력에서 실제로
울리는가」를 함께 고정한다.

셋은 같은 성질이며 층만 다르다. R-11 은 "정상 0건과 요청 실패가 바이트 단위로
동일하다"고 적었는데, 안전망이 돌지 않는 상태도 정상과 바이트 단위로 같다.
**방어를 한 겹 안쪽에 놓아도 같은 병에 걸린다** — 그래서 관측을 둘로 두는 것
(카나리아 / 재계산 / 두 조회의 대조)이 이 저장소가 반복해 쓰는 유일한 대응이다.
