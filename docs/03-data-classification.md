# 03. 데이터 분류

## 이 문서의 목적

이 시스템이 다루는 데이터를 민감도로 분류하고, 각 등급이 **어디까지 갈 수 있는지**를
정한다. 특히 "모델 공급자에게 전송해도 되는 데이터"의 경계를 명시한다. 이 경계를 문서로
정하지 않으면 프롬프트를 만드는 사람이 매번 즉석에서 판단하게 되고, 판단은 시간이 지나며
느슨해진다.

## 0. 비중요업무 분류 논거 — 이 절이 도입 심의의 핵심이다

전자금융감독규정은 클라우드 이용 시 **중요도 평가**를 요구한다(조항 번호는
`02-regulatory-mapping.md` B-1 — **원문 확인 전까지 TODO(verify)**). 중요업무로 분류되면
심의·보고 절차와 안전성 확보조치 요구가 크게 무거워진다.

**이 시스템이 개인정보를 처리하지 않는 것은 설계 선택이었고, 그 선택이 규제 비용으로
직접 환산된다.**

| 사실 | 근거 | 분류에 대한 함의 |
|---|---|---|
| 입력이 법령 원문과 사내 규정 문서뿐이다 | CLAUDE.md §2-3 (설계상 배제) | 개인정보 처리 시스템이 아니다 |
| 고객 거래 데이터에 접근하지 않는다 | 원칙 5 — DB 읽기 전용 role, 접근 대상은 규정·법령 테이블 | 전자금융거래 처리 시스템이 아니다 |
| 어떤 실행도 승인 없이 일어나지 않는다 | 원칙 4 — 그래프 레벨 승인 | 자동 의사결정 시스템이 아니다 |
| 장애 시 업무가 수동으로 계속된다 | 대체 수단 = 현행 수동 모니터링 | 가용성 요구가 낮다 |
