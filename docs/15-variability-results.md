## 1. 한 줄 요약

**집계 지표는 거의 흔들리지 않는데 케이스 단위로는 15건 중 10건이 흔들린다.**
그리고 흔들리는 층이 정해져 있다 — **"무엇을 찾는가"는 완전히 안정적이고,
"그것을 어떻게 판정하고 누구에게 배정하는가"가 불안정하다.**

## 2. 두 경로를 따로 쟀다

| 경로 | 반복 | 결과 |
|---|---|---|
| **검색** (임베딩 → BM25 → RRF) | 3회 | **완전 일치.** 15케이스 × 3모드, 점수까지 동일 |
| **LLM** (추출 → 초안 → 검증) | 3회 | 아래 §3~§4 |

검색 경로가 결정론적이라는 것을 **단정하지 않고 쟀다.** 부동소수 연산이나 배치 크기로
흔들릴 여지가 이론적으로 있었고, 무료이므로 재면 될 일이었다.

### 이 결과가 §1-1 의 분류를 정정한다

`docs/12-impact-assessment-results.md` §1-1 은 KURE 채택과 HYBRID 채택을 「변동성이
차이보다 작다는 가정 위에 있는 결론」으로 분류했다. **틀린 분류였다.**

두 결정 모두 **검색 경로**의 측정이고, 그 경로의 변동성은 **0** 이다. 두 결론의 실제
취약점은 변동성이 아니라 **표본 15건**이며, 그것은 6단계 §4 골든셋 확장이 답한다.

HYBRID 는 동률로 결정했으므로 「차이 > 편차」 부등식으로는 영원히 유지될 수 없다
(`0 > 0` 은 거짓이다). 규약 §4.3 에 미리 적어 둔 대로 **tie-break 규칙의 타당성 문제**로
재분류한다 — 변동성 문제가 아니다.

## 4. 케이스 단위 — **10/15 가 흔들린다**

집계는 상쇄될 수 있으므로 케이스마다 세 값을 대조했다
(`impact_status` / `hit` / `departments`, 규약 §3.2).

| 케이스 | 정답 | HARD | 흔들린 값 |
|---|---|---|---|
| case-001 | IMPACT | ● | departments |
| case-003 | **NO_IMPACT** | | departments, **impact_status** |
| case-004 | IMPACT | ● | impact_status |
| case-005 | IMPACT | ● | impact_status |
| case-007 | IMPACT | ● | hit, impact_status |
| case-008 | IMPACT | ● | departments |
| case-009 | IMPACT | | departments |
| case-010 | IMPACT | ● | departments |
| case-012 | IMPACT | ● | hit |
| case-013 | **INSUFFICIENT_EVIDENCE** | | departments, **impact_status** |

**불안정 10건 중 7건이 HARD**(정답이 2개 이상 문서에 걸친 케이스)다.

### 4.1 층이 갈린다

| 흔들리는 값 | 건수 | 의미 |
|---|---|---|
| `hit` (정답 문단) | **2** | 무엇을 찾는가 — **거의 안정적** |
| `impact_status` | 5 | 어떻게 판정하는가 |
| `departments` | 6 | 누구에게 배정하는가 |

`hit` 이 흔들린 2건도 **케이스 적중은 유지**됐다 — 정답 문단 하나는 매번 찾고, 두 번째
문단을 찾았다 말았다 한다(case-007 의 `ISP-GUIDE-003#6`, case-012 의 `ISP-GUIDE-003#31`).

### 4.2 가장 나쁜 것 — case-003

| 회차 | 상태 |
|---|---|
| 1 | `NEEDS_REVIEW` |
| 2 | `OK` |
| 3 | `INSUFFICIENT_EVIDENCE` |

**정답은 `NO_IMPACT`다** (타법개정, 인용 항 번호 한 줄만 바뀐 케이스).
셋 다 오답인데 **틀리는 방식이 매번 다르다.** 담당자가 같은 개정을 두 번 넣으면
한 번은 "검토 필요", 한 번은 "근거 확보", 한 번은 "이관"을 받는다.

### 4.3 case-013 은 3회 모두 놓쳤다

| 회차 | 상태 |
|---|---|
| 1 | `OK` |
| 2 | `NEEDS_REVIEW` |
| 3 | `OK` |

정답은 `INSUFFICIENT_EVIDENCE` 다. 4단계에서 gate 3단이 놓친 그 케이스이며(§12.3),
**세 회차 모두 놓쳤다.** 이것은 변동성이 아니라 **일관된 실패**다 — 그래서 오히려
재현 가능한 결함이고, 6단계 §3 적대적 세트의 adv-009 가 같은 자리를 겨냥한다.

### 4.4 부서 이름이 회차마다 다르게 쓰인다 — R-24 의 실측 증거

```
case-013 :  '개인정보 보호책임자'  /  (없음)  /  '개인정보 보호책임자(개인정보보호 조직)'
case-009 :  '정보보호부'  /  '각 부서(현업부서)', '정보보호부'  /  '정보보호부'
case-010 :  '경영진(대표이사 등)', '준법감시부'  /  (없음)  /  '경영진(대표이사 등)', '정보보호부'
```

같은 대상을 다른 문자열로 부른다. **R-24(부서 배정이 조직도와 대조되지 않는다)가
가설이 아니라 관측이 됐다** — 자유 텍스트이므로 집계도, 티켓 라우팅도 성립하지 않는다.

## 5. 판정 — 규약 §4 를 그대로 적용한다

### 5.1 전역 기준 → **재검토**

```
케이스 단위 불안정 ≤ 1건  그리고  IMPACT 적중 편차 ≤ 1건   →  유지
```

- IMPACT 적중 편차 **0** ✓
- 케이스 단위 불안정 **10건** ✗

**AND 조건이므로 전체 판정은 「재검토」다.**

### 5.2 결론별 개별 판정 (규약 §4.3) → **전부 유지**

```
결론이 근거로 삼은 차이  >  관측된 편차   →  유지
```

| 결론 | 근거 차이 | 관측 편차 | 판정 |
|---|---|---|---|
| KURE-v1 채택 (ADR-015) | 재현율 0.05 | **0** (검색) | **유지** |
| 위임 승격 N=2 (ADR-017) | 0.7667 → 0.8167 | **0** (검색) | **유지** |
| HYBRID 채택 (ADR-016) | 동률 | 0 (검색) | 변동성 문제 아님 → **tie-break 타당성으로 재분류** |
| 재작성 종료 `MAX_REVISIONS=0` | IMPACT 적중 1건 | **0** (적중 집합까지 동일) | **유지** |
| de-anchored 기각 | 적중 3건, 부서 재현율 0.45 | 적중 0, 부서 0.05 | **유지** |

### 5.3 두 판정이 모순이 아니다

**지금까지의 결론은 흔들리지 않는다. 그러나 시스템은 케이스 단위로 불안정하다.**

두 문장이 동시에 참이다. 기준이 두 가지를 함께 요구한 이유가 이것이며, 하나만 봤다면
"편차 0, 결론 확정"으로 끝내고 **10건이 흔들린다는 사실을 못 봤을 것이다.**

## 6. `MAX_REVISIONS = 0` 이 예고대로 나왔다

§12.7 은 전수 관측으로 "0 으로 두는 대가는 IMPACT 적중 9/10 → 8/10, 즉 1건"이라고
계산해 뒀다. **3회 실측이 8/10 을 세 번 재현했다.**

| | 4단계 (`=1`) | 6단계 3회 (`=0`) |
|---|---|---|
| IMPACT 적중 | 9/10 | **8/10** (3회 동일) |
| 재작성 | 5건 | **0건** |
| 이관 | 4/15 | 5~6/15 |
| 비용 | $2.6333 | **$2.0697** (평균) |

**비용이 21.4% 줄었다.** 3회 합계 $6.2090, 사전 확인 1건 $0.1847 포함 **$6.3937**.
예상($6 안팎)과 일치한다.

| §1-1 이 미확인으로 남긴 것 | 지금 상태 |
|---|---|
| 변동성의 크기를 모른다 (집계 지표) | **닫힘.** 3회 측정, IMPACT 적중 편차 0, 부서 재현율 편차 0.05 |
| KURE·HYBRID 가 변동성에 취약한가 | **닫힘.** 검색 경로 편차 0 — 애초에 변동성 문제가 아니었다 |
| 재작성 종료·de-anchored 기각의 근거가 잡음인가 | **닫힘.** 근거 차이 > 편차 |
| **케이스 단위 안정성** | **열렸다.** 이 측정 전에는 아무도 재지 않았다 |

**닫으면서 새로 연다.** 집계 편차가 작다는 사실은 케이스가 안정적이라는 뜻이 전혀
아니었고, 그것을 이번에 수치로 확인했다.
