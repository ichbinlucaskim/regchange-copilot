## 맥락

1단계에서 조문 파서를 만들면서 `xml.etree.ElementTree`를 썼고, ruff **S314**가 이를
잡아냈다 — *"Using `xml` to parse untrusted data is known to be vulnerable to XML
attacks; use `defusedxml` equivalents."*

`pyproject.toml`에는 0.7단계에 이렇게 미뤄 둔 주석이 있었다:

> S314: 신뢰된 로컬 픽스처만 파싱한다. **TODO(verify): `src/`의 실제 파서는
> `defusedxml` 사용 여부를 ADR로 결정한다.** 이 면제를 `src/`로 확대하지 않는다.

그 결정을 할 시점이 왔다. `src/regchange/parse/`는 **외부 HTTP 응답**을 파싱한다.

---

## 결정

- **`src/`의 XML 파싱은 `defusedxml`을 쓴다.** 의존성으로 `defusedxml`과
  `types-defusedxml`을 추가한다.
- **`scripts/`의 탐색 도구는 표준 `xml.etree`를 유지한다.**
  `pyproject.toml`의 `per-file-ignores`에 `S314`를 남긴다.
- `pyproject.toml`의 미뤄 둔 주석을 이 ADR 참조로 교체한다.

---

## 목적

외부 HTTP 응답을 파싱할 때 XXE(외부 엔티티 참조), 확장 폭탄(billion laughs),
DTD 기반 공격의 표면을 제거한다.

---

## 구현 이유

### "공공 API이므로 신뢰할 수 있다"는 가정을 쓰지 않는다

법제처 API 응답은 **우리가 통제하지 않는 외부 입력**이다. 제공자가 정부 기관이라는
사실은 전송 경로가 안전하다는 뜻도, 응답이 항상 우리가 기대한 형태라는 뜻도 아니다.

**신뢰 경계는 데이터의 출처로 정해지지 제공자의 평판으로 정해지지 않는다.**
이것이 원칙 5가 말하는 것과 같은 구조다 — 원칙 5는 "LLM이 나쁜 짓을 할 것 같아서"
읽기 전용 role을 쓰는 것이 아니라, **권한이 없으면 피해가 성립하지 않기 때문에** 쓴다.

### `scripts/`를 예외로 두는 이유

탐색 도구는 **로컬 픽스처만 읽는다.** 픽스처는 이미 OC 마스킹을 거쳐 저장소에 커밋된
내부 데이터이며, 변경은 코드 리뷰를 통과해야 한다.

**신뢰 경계가 다르므로 다른 규칙이 적용된다.** 그리고 그 경계를
**코드 위치(`src/` vs `scripts/`)로 표현한 것이 이 결정의 핵심이다** —
주석이나 관행이 아니라 디렉터리 구조와 린트 설정이 경계를 강제한다.

| | `src/regchange/parse/` | `scripts/exploration/`, `scripts/analysis/` |
|---|---|---|
| 입력 출처 | 외부 HTTP 응답 | 로컬 픽스처 |
| 검토 여부 | 없음 (런타임 수신) | 코드 리뷰를 거쳐 커밋됨 |
| 파서 | `defusedxml` | `xml.etree` |
| S314 | 적용 | `per-file-ignores`로 면제 |

### 신뢰 경계 결정의 계보

이 ADR은 단독 결정이 아니라 같은 발상의 연속이다.

| 결정 | 내용 |
|---|---|
| edge-case #1 | OC가 응답에 echo된다 → **저장 전** 마스킹, 실패 시 저장 거부 |
| ADR-005 | 응답 형태를 분류한다 → `raise_for_status()`를 믿지 않는다 |
| ADR-007 | 파싱된 식별자의 **출처를 표시한다** |
| **ADR-012** | 외부 입력 파서를 **분리한다** |

넷 다 "외부에서 온 것을 외부에서 온 것으로 다룬다"는 같은 규칙의 다른 적용이다.

## 제품 철학과의 연결

직접적인 연결은 약하다 — 이것은 사용자의 선택을 다루는 결정이 아니라 보안 통제다.
**그 사실을 숨기지 않는다.** 모든 ADR이 제품 철학과 강하게 연결될 필요는 없다.

간접적인 연결은 있다. 파서가 공격받아 잘못된 트리를 만들면 인용이 가리키는 대상이
바뀌고, 담당자는 **틀린 근거 위에서 검토하게 된다.** 그때 담당자의 "검토"는 검토가
아니다 — 시스템이 제공한 사실이 사실이 아니었으므로, 그 위의 판단은 담당자의 판단이
아니라 시스템의 오류다. 근거의 무결성은 "선택에 이르는 과정"의 최소 조건이다.

이 결정을 뒤집으면(표준 파서 사용) 그 무결성이 **입력을 보낸 쪽에 위임된다.**

## 트레이드오프

**포기한 것**

- 표준 라이브러리만으로 끝내는 단순함. 의존성이 1개(타입 스텁 포함 2개) 늘었다.
- `defusedxml`이 일부 XML 기능을 막는다. 향후 필요한 기능(커스텀 엔티티 등)을 쓰지
  못할 수 있다. 관측 범위에서 필요한 기능은 없었다.
- 파서가 두 종류가 되어, 새 코드를 어디에 두느냐에 따라 규칙이 달라진다.

**얻은 것**

공격 표면 제거. 그리고 **ruff S314를 예외 처리 없이 통과한다** — `noqa` 주석이나
디렉터리 예외를 `src/`에 추가하지 않았다. 예외가 없으면 나중에 느슨해질 여지도 없다.

**이 선택이 틀렸음을 알게 되는 신호**

1. **`defusedxml`이 표준 파서와 다르게 파싱해 픽스처 테스트가 깨진다.**
   현재까지 파서 정확도 1.0000(1,957/1,957)으로 차이가 관측되지 않았다.
2. **법제처가 `defusedxml`이 막는 XML 기능을 쓰기 시작한다.** 파싱 실패로 즉시
   드러난다 — 조용히 잘못 파싱되는 것이 아니라 예외가 난다.
3. **`scripts/`가 네트워크를 직접 호출하기 시작한다.** 예외 규칙의 전제가 깨진다.
4. **`src/`에 `noqa: S314`가 등장한다.** 경계가 실제 코드 구조와 맞지 않는다는 뜻이다.
   예외를 늘리지 말고 경계를 다시 긋는다 (ADR-010 신호 2와 같은 규칙).

**되돌리는 비용**

| 방향 | 비용 |
|---|---|
| `defusedxml` 제거 | **낮다.** import 문 교체 수준이다. 파서 로직은 그대로다 |
| 나중에 도입 | **낮다.** 마찬가지로 import 교체다. 다만 그 사이 수신한 응답은 표준 파서를 거쳤고, 그 시점에 공격이 있었는지는 **사후에 알 수 없다** |

**되돌리기가 양방향으로 싸다는 점이 이 결정을 쉽게 만든다.** 비용이 낮으므로 보수적인
쪽을 기본값으로 둔다.

## 엣지 케이스

- **`defusedxml`이 지원하지 않는 XML 기능을 법제처가 쓰는 경우**: 파싱 실패로 예외가
  난다. 조용히 다른 결과를 내지 않는다 — 이것이 표준 파서보다 나은 실패 방식이다.
- **CDATA 처리가 표준 파서와 동일한가**: 응답에 CDATA 블록이 파일당 1,126개 있다
  (edge-case #16). 픽스처 13개 문서 1,957 조문단위를 전부 파싱해 재구성 정확도
  1.0000을 확인했으므로 **동일하다고 검증됐다.**
- **`scripts/`가 나중에 네트워크를 직접 호출하는 경우**: `src/`의 클라이언트를 쓰거나
  이 ADR을 개정한다. 예외 규칙을 조용히 유지하지 않는다.
- **`xml.etree`의 타입을 계속 쓰는 경우**: `defusedxml`은 파싱 함수만 대체하고 반환
  타입은 표준 `Element`다. 타입 힌트는 `xml.etree.ElementTree.Element`를 그대로 쓴다 —
  이것은 파싱 경로가 아니므로 S314 대상이 아니다.
- **JSON 응답으로 전환하는 경우**: 이 ADR의 적용 대상이 아니다. 다만 JSON에서는
  CDATA 보호가 없어 본문 마커 처리를 재검증해야 한다 (`law-api-spec.md` §8).
