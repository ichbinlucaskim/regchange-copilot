# ADR-015: 임베딩은 로컬 모델을 쓰고, 후보 선택도 로컬 모델끼리 측정해서 정한다

| | |
|---|---|
| **상태** | 채택됨 |
| **일자** | 2026-08-20 |
| **결정자** | 프로젝트 저자 (1인 프로젝트) |
| **검토자** | 없음 — 실무자 인터뷰로 사후 검증 예정 |
| **관련 원칙** | 원칙 2 (인용은 필수), 원칙 5 (LLM 경로의 권한 경계) |
| **관련 ADR** | ADR-010 (어댑터 경계), ADR-002 (정규화), ADR-016 (검색 결합) |

---

## 맥락

3단계에서 사내 규정 152조를 벡터로 색인해야 한다. `.env.example` 은 `LLM_PROVIDER` /
`LLM_MODEL` 을 빈 값으로 두고 **"1단계에서 평가 결과로 확정한다"** 고 적어 두었다.
임베딩도 같은 성질의 결정이며, 지금이 그때다.

**이 결정은 되돌리기 비싸다.** 모델을 바꾸면 코퍼스를 통째로 재인덱싱해야 하고, 그
시점에 평가 결과가 쌓여 있으면 "모델을 바꿔서 좋아진 것인가 다른 것이 바뀐 것인가"를
가를 수 없다. 그래서 미룰 수 없다 — 미루면 미확정 상태로 쌓인 측정치가 전부 재작업이 된다.

이 저장소는 도메인 선택(ADR-008), diff 채점 기준, 조문 이동 판정을 전부 **측정으로**
정해 왔다. 임베딩만 감으로 정하면 그 일관성이 깨진다.

---

## 결정

**임베딩은 로컬 모델만 후보로 놓고, 로컬 모델 2종을 같은 골든셋으로 재서 고른다.**
상용 API 임베딩(OpenAI, Cohere)은 **후보에서 제외한다** — 운영에서 쓸 수 없기 때문이며,
쓸 수 없는 것과 비교해 고르는 것은 선택에 정보를 주지 않는다.

대조 대상은 `BAAI/bge-m3` 와 `nlpai-lab/KURE-v1` 이고, 채점 규약은
`docs/10-retrieval-evaluation-protocol.md` 에 **측정 이전에** 고정했다.
결정 지표는 재현율@10, 동률 시 DECOY 혼입률@10.

**측정 결과 KURE-v1 을 채택한다** (재현율@10 = 0.7667 vs 0.7167).

---

## 목적

사내 규정 문단을 벡터로 표현하되, **그 벡터를 만드는 과정이 은행 환경에서 실행 가능한
형태**로 남게 한다. 검색 품질과 배포 가능성 중 하나를 나중에 포기하는 상황을 만들지 않는다.

---

## 구현 이유

### 왜 상용 API 를 후보에서 뺐는가

사내 내부통제 규정 원문을 외부 API 로 보내는 것은 은행에서 실제로 걸리는 지점이다.

**전자금융감독규정 제14조의2가 클라우드컴퓨팅서비스 이용에 관한 조항이라는 것은 원문으로
확인했다** — 전자금융감독규정시행세칙 제2조의4(클라우드컴퓨팅서비스의 보고, 시행
2026-04-20, law.go.kr `admrul` ID `2200000108629`)가 규정 제14조의2를 인용하며 아래를
열거한다:

| 인용 | 내용 |
|---|---|
| 제14조의2제1항제1호 | 업무의 중요도 평가 기준 및 결과 |
| 제14조의2제1항제2호 | 클라우드컴퓨팅서비스 제공자의 건전성 및 안전성 등에 대한 평가 결과 |
| 제14조의2제1항제3호 | 업무 연속성 계획 및 안전성 확보조치에 관한 사항 |
| 제14조의2제2항 | 정보보호위원회 심의ㆍ의결 결과 |
| 제14조의2제4항 | 감독원장 보고 |

**외부 임베딩 API 호출이 이 조항의 적용을 받는지는 우리가 판정할 사항이 아니다.**
그 판단은 법무·컴플라이언스와 감독당국 질의의 영역이며, 이 시스템은 법률 해석을 하지
않는다 (CLAUDE.md §2.6). 여기서 확인된 것은 **"판단을 받아야 하는 절차가 존재한다"**
는 사실뿐이고, 그것만으로 충분하다 — 절차를 통과해야 하는 경로와 통과하지 않아도 되는
경로가 있다면, 후자가 존재한다는 것 자체가 설계상 가치다.

개인정보를 포함하지 않는다는 점은 이 판단을 바꾸지 않는다. 이 시스템은 개인정보를
설계상 배제하지만(CLAUDE.md §2.3), 내부통제 규정 문서는 그것과 별개로 대외비다.

### 왜 이 두 모델인가

| 항목 | `BAAI/bge-m3` | `nlpai-lab/KURE-v1` |
|---|---|---|
| 차원 | 1024 | 1024 |
| 최대 시퀀스 | 8192 | 8192 |
| 파라미터 | 567,754,752 | 567,754,752 |
| 라이선스 | MIT | MIT |
| 관계 | 다국어 범용 | **bge-m3 를 한국어로 파인튜닝** |
| 개발 | BAAI | 고려대 NLP&AI Lab |

(출처: 각 모델의 Hugging Face 모델 카드 및 `api/models` 메타데이터, 2026-08-20 조회)

**KURE-v1 이 bge-m3 의 한국어 파인튜닝이라는 점이 이 대조를 고른 이유다.** 차원·시퀀스
길이·파라미터 수가 전부 같으므로 **변수가 "한국어 특화 학습" 하나만 남는다.** 결과가
갈리면 그 원인이 무엇인지 해석할 여지가 없다.

`intfloat/multilingual-e5-large` 도 후보였고 탈락시켰다. 아키텍처 계열이 다르고
(559,890,946 파라미터), 질의·문서 접두어 방식도 다르다 — 세 가지가 동시에 바뀌면
"한국어 특화가 이득인가"라는 질문에 답할 수 없다. 대조를 하나 더 늘리는 대신 대조가
답하는 질문을 선명하게 두었다.

### 대안

| 대안 | 장점 | 택하지 않은 이유 |
|---|---|---|
| OpenAI `text-embedding-3-large` 와 대조 | 품질 상한을 알 수 있다 | **운영에서 못 쓴다.** ADR 에 "운영 시 대체한다"를 적게 되는 모델과 비교해 고르는 것은 선택에 정보를 주지 않는다 |
| 로컬 대조 없이 bge-m3 채택 | 측정 1회를 아낀다 | "측정으로 정했다"가 아니라 "외부 전송을 피하려고 정했다"가 된다. 이 저장소의 다른 결정과 일관되지 않는다 |
| 임베딩 없이 어휘 검색만 | 가장 단순 | MEDIUM 케이스(법령과 다른 어휘)가 골든셋의 21항목이다. ADR-016 의 측정이 이 판단의 근거다 |

### 측정 결과

`docs/10-retrieval-evaluation-results.md` §2. 벡터 단독, 골든셋 15건, k=10.

| 모델 | 재현율@10 | DECOY@10 | EASY | MEDIUM | HARD |
|---|---|---|---|---|---|
| bge-m3 | 0.7167 | 0.3556 | 1.0000 | 0.6190 | 0.6522 |
| **KURE-v1** | **0.7667** | 0.3556 | 1.0000 | **0.6667** | **0.6957**  |

DECOY 혼입률이 같으므로 tie-break 는 발동하지 않았다. **한국어 특화 학습이 MEDIUM
(법령과 다른 어휘를 쓰는 조항)에서 이득을 준다** — 정확히 그 축에서 갈렸다.

## 트레이드오프

### 무엇을 얻었는가

- **사내 규정 원문이 프로세스 밖으로 나가지 않는다.** 클라우드 심의를 통과할 수 있느냐와
  무관하게, **통과하지 않아도 되는 경로가 있다.**
- 호출당 비용 0. 골든셋 반복 평가가 무료이므로 6단계 확장에서도 측정을 아끼지 않는다.
- 네트워크 실패가 검색 실패가 되지 않는다.

### 무엇을 포기했는가

**상용 API 임베딩과의 품질 격차를 모른다. 측정하지 않았다.**

측정하지 않은 이유는 운영에서 사용할 수 없기 때문이며, 선택지에 없는 것과 비교해 고르는
것은 의미가 없다고 판단했다. 이것은 결함이 아니라 **의도적인 공백**이고, 공백이라는
사실을 여기 적는 것이 이 절의 목적이다.

그 외에 포기한 것:

- torch 의존과 약 2GB 모델 가중치. `eval` 의존성 그룹으로 격리했으므로 수집·파싱·차분
  경로는 영향이 없다.
- 추론 속도. 152조 색인이 약 30초(Apple Silicon MPS), 질의 건당 수백 밀리초다.
  배치에서는 문제가 아니지만 **대화형 검토 UI(4단계)에 붙일 때 다시 재야 한다.**

### 틀렸음을 알게 되는 신호

**로컬 모델의 검색 재현율이 목표에 미달하고, 그 원인이 임베딩 품질로 밝혀질 때.**

"미달"과 "임베딩 탓"은 다른 판정이다. 후자를 주장하려면 어휘 검색(ADR-016)에서도 같은
항목이 실패해야 한다 — 두 방식이 같은 방향으로 실패하면 임베딩이 아니라 문제 구조다
(실제로 R-22 가 그 형태다).

그 신호가 확인되면 **금융 클라우드 전용 리전의 임베딩 서비스**를 검토한다. 공개 인터넷
API 로 되돌아가는 것이 아니라, 심의 절차를 통과할 수 있는 형태를 찾는 것이다.

### 되돌리는 비용 — 비대칭이다

| 방향 | 비용 |
|---|---|
| 로컬 → 다른 로컬 모델 | **낮음.** `LocalEmbeddingClient("<name>")` 인자 하나. 차원이 같으면 재인덱싱 30초, 달라도 스키마 변경 없음(`policy_paragraph_embedding` 이 `(paragraph_id, model_id)` 키에 차원을 행 단위로 갖는다) |
| 로컬 → 외부 API | **높음.** 코드는 `EmbeddingClient` 구현 교체로 끝나지만(ADR-010), **클라우드 이용 심의·정보보호위원회 의결·감독원장 보고 절차가 앞에 붙는다.** 되돌리는 비용의 대부분이 코드 밖에 있다 |
| 외부 API → 로컬 | 낮았을 것이다. 그래서 **비싼 방향을 나중에 열어 두는 순서**를 택했다 |

## 제품 철학과의 연결

이 결정은 "선택에 이르는 과정"에 간접적으로 이어진다. 검색은 담당자가 **읽는 단계**를
돕는 기능이고, 임베딩은 그 안쪽의 구현이다.

**뒤집으면 어디에서 사용자의 선택을 대신하게 되는가**: 뒤집어도 사용자의 선택을 대신하지는
않는다. 대신 **다른 것을 대신한다** — 외부 API 를 쓰기로 하면 "이 문서를 밖으로 보내도
되는가"라는 판단을 시스템이 이미 내려 버린 상태로 담당자에게 도착한다. 그 판단은
정보보호위원회의 것이지 이 시스템의 것이 아니다. 이 ADR 은 그 판단을 **미결 상태로
남겨 두는 쪽**을 택한 것이다.

## 축 연결

- **축 2 (환경) — 주된 기여.** ADR-010 과 ADR-012 에 이은 세 번째 축 2 ADR 이다.
  **어댑터 경계 뒤에 두는 것만으로는 축 2 가 아니다.** 축 2 는 "왜 이 형태여야 하는가"에
  **규제 근거**가 붙을 때 성립한다. 여기서는 전자금융감독규정 제14조의2 의 존재를 원문으로
  확인하고, 그 절차를 통과하지 않아도 되는 경로를 선택했다.
- **축 3 (운영)** — 부수적. 호출 비용 0 이므로 반복 측정이 운영 부담을 만들지 않는다.
- **축 1 (업무)** — 기여하지 않는다. 담당자 업무 흐름과 무관한 내부 구현 선택이다.

## 엣지 케이스

- **모델을 내려받을 수 없음(오프라인·망분리)**: 예외를 그대로 전파한다. "임베딩 없이
  계속"하는 경로를 만들지 않는다 — 벡터 없는 검색은 다른 검색이며, 그 차이가 지표에
  드러나지 않는다. 망분리 환경에서는 가중치를 사전 반입한다.
- **모델 교체 시 이전 벡터와의 혼입**: `policy_paragraph_embedding` 의 기본키가
  `(paragraph_id, model_id)` 이고, 검색 질의가 `model_id` 로 필터한다. 두 모델의 벡터가
  한 순위에 섞일 수 없다.
- **차원 불일치**: 어댑터가 반환 직후 검사하고, DB `CHECK (vector_dims(embedding) = dim)`
  이 다시 잡는다. 두 겹인 이유는 어느 쪽이 먼저 실패해도 원인이 같은 곳을 가리키게 하기
  위해서다.
- **빈 문자열 임베딩**: `ValueError`. 영벡터는 코사인 거리가 정의되지 않아 순위가 임의로
  정해진다 — fail-closed 다.
- **원칙 5 와의 관계**: 임베딩 생성은 `app_policy` role 로 하고, LLM 경로(`app_graph`)는
  임베딩 테이블에 SELECT 만 갖는다. 검색 결과를 조종하려면 벡터를 바꿔야 하는데, LLM 이
  관여하는 프로세스에는 그 권한이 없다 (`009_policy_corpus.sql`,
  `tests/security/test_policy_corpus_role.py`).
