# 보안 메모

이 저장소의 코드가 아니라 **다루는 대상의 성질**에서 오는 보안 사항을 모은다.
설계 결정은 ADR에, API 사실은 `api-exploration/`에 있다.

---

## 1. 법제처 OC는 교체할 수 없는 자격증명으로 가정한다

### 관측된 사실

| 사실 | 확인 여부 |
|---|---|
| OC가 응답 본문에 그대로 echo된다 — `법령상세링크`, `조문링크`, `조문변경이력상세링크` 필드가 요청 URL을 통째로 담는다 | O 실측 (`search_law_teukgeum.xml`, `dayjochg_regdt20250401.xml`, edge-case #1) |
| 활용가이드의 OC 설명은 **"신청한 API인증값"** 한 줄이 전부다 | O 확인 (`guideResult.do?htmlName=lsNwListGuide` 등) |
| OC가 회원 이메일 아이디를 사용하며 **재발급해도 값이 같다** | X **미확인.** 활용가이드·이용안내 어디에도 명시되어 있지 않다 |

### 운영 규칙

**회전 가능 여부가 확인될 때까지 "교체할 수 없는 자격증명"으로 가정하고 다룬다.**
즉 유출 시 대응 수단이 "교체"가 아니라 **노출 최소화**뿐이라고 전제한다.

- 응답을 저장·로깅하기 전에 마스킹한다. 마스킹 실패 시 저장을 **거부**한다
  (`scripts/exploration/fetch.py`, `scripts/analysis/amendment_frequency.py`).
- 응답 본문을 그대로 터미널에 출력하지 않는다. 마스킹을 거치는 헬퍼만 쓴다.
- 캐시 디렉터리(`data/frequency-cache/`)는 `.gitignore`에 있다.

### 이 규칙을 강제하는 테스트

`tests/security/test_fixture_credentials.py`가 **모든 픽스처의 `OC=` 값이 마스킹
토큰(`***`)인지 CI에서 상시 검사한다.** `.env` 없이 동작하므로 어느 환경에서나 돈다.

**이 테스트를 제거하지 않는다.** 회전이 불가능하다는 가정이 맞다면 이것이 사실상 유일한
방어선이다. CLAUDE.md §6의 "security 테스트는 리팩터링 편의로 삭제하거나 skip 하지 않는다"에
해당한다.

### 확인 방법

법제처 공동활용 유지보수팀(활용가이드에 안내된 번호)에 재발급 시 값이 바뀌는지 문의하거나,
실제로 재발급을 신청해 값을 대조한다. 확인되면 이 문서를 갱신한다.

### 알려진 노출 이력

0.7단계 탐색 초기에 응답 원문을 마스킹 없이 터미널에 출력해 **작업 세션 로그에 OC가 한 번
노출됐다.** 저장소·픽스처에는 유출되지 않았고(스캔 확인), 이후 출력은 전부 마스킹을 거친다.
세션 로그가 보관되는 환경이라면 OC 재발급을 검토한다 — 다만 위 "미확인" 항목대로
재발급으로 값이 바뀌는지 자체가 확인되지 않았다.

## 2. 개인정보를 다루지 않는 것은 설계 선택이다

이 시스템의 입력은 **법령 원문과 사내 규정 문서**이며 개인정보가 들어오지 않는다
(CLAUDE.md §2-3). 이것은 기능 미구현이 아니라 범위 배제이며, 규제 부담을 낮추는 방향으로
작용한다. 근거와 영향은 `docs/03-data-classification.md`에 정리한다.

**이 전제가 깨지는 순간**을 감시한다: 사내 규정 문서에 개인정보가 예시로 포함되거나,
승인자 정보가 필요 이상으로 수집되는 경우다.

## 3. LLM 프로세스의 권한 경계

원칙 5에 따라 LLM이 관여하는 프로세스는 **읽기 전용 DB role**을 쓴다. 이 경계는 애플리케이션
조건문이 아니라 DB 권한으로 강제하며, `tests/security/test_readonly_db_role.py`가 실제 DB를
상대로 `CREATE TABLE`·`CREATE SCHEMA`가 거부되는지 검사한다.

프롬프트 인젝션이 성립하더라도 쓰기 권한이 없으면 피해가 조회로 제한된다.
관련 설계는 ADR-010(`identity/` 어댑터)에서 이어진다.

## 4. 킬 스위치는 fail-closed다

`LLM_ENABLED`·`RETRIEVAL_ENABLED`·`DISPATCH_ENABLED`의 기본값은 **꺼짐**이다.
설정 누락·조회 실패는 전부 "꺼짐"으로 수렴한다 — **모르면 안 한다.**

**2026-08-21 부터 실동작한다** (ADR-019). 그전까지는 `.env.example` 의 세 줄과 그 값을
검사하는 테스트만 있었고 **읽는 코드가 없었다.** 지금은 상태가 `kill_switch` 테이블에
있고(bitemporal, 누가 언제 왜 바꿨는지가 행으로 남는다), `guards/killswitch.py` 가
검색·모델 호출·발송의 진입에서 검사하며, 꺼져 있으면 **예외로 멈춘다** — 빈 결과를
돌려주지 않는다. 빈 결과는 하류에서 "영향 없음"으로 읽히기 때문이다.

멈춘 이유는 셋으로 구별된다: `OFF`(누가 껐다) / `NEVER_SET`(켠 적 없다) /
`UNAVAILABLE`(상태를 못 읽었다). 조치가 다르므로 값이 다르다.

**어떤 서비스 role 도 스위치를 켤 수 없다.** 쓰기 권한은 소유자에게만 있고, 인젝션이
성립하더라도 스위치를 켜는 경로가 없다. `tests/security/test_kill_switches.py` 가
발화(꺼면 실제로 안 도는가)와 권한(LLM role 이 못 켜는가)을 함께 검사한다.

## 5. 외부 API 호출 시 지켜야 할 것

- 호출 간 **1.2초 이상** 간격. 공공 API에 부담을 주지 않는다.
- 캐시가 있으면 재호출하지 않는다.
- 대량 수집을 하지 않는다. 구조 파악·측정에 필요한 최소한만 받는다.
- 응답 형태를 분류해 실패를 0으로 세지 않는다 (ADR-005의 R-11).
